## Calculator interaction

The UI should behave like an intuitive calculator rather than exposing raw API payload forms.

For operations that accept multiple operands:
- addition
- multiplication
- division

once an operation is selected, subsequent operands must continue using that same operation.

For example, addition may produce:

1 + 1 + 1 + 1

but it should not allow mixing operators into something like:

1 + 1 * 2

because arbitrary expression parsing is intentionally outside the backend scope.

Allow the user to continue adding operands for these operations.

Handle incomplete input states safely. For example:

1 + 1 + 1 +

must not be submitted because there is no operand after the final operator. Disable calculation or otherwise prevent submission until the expression is complete.

For operations with fixed mathematical inputs, constrain the UI accordingly:

- Square root requires one radicand. Once the user enters a value and chooses square root, no additional operand is required.
- Exponentiation requires exactly a base and an exponent.
- Percentage requires exactly a value and a percentage. After selecting percentage, only the additional percentage input required by the backend contract should be accepted.

The frontend interaction should reflect the actual backend contracts rather than creating unsupported expression semantics.

## Intuitive UI

Provide an intuitive UI for entering inputs and displaying results.

- show a visible loading state
- disable calculator buttons and inputs that could trigger or modify the current calculation
- prevent duplicate requests
- restore interaction after the request completes, whether it succeeds or fails

Display the result clearly after a successful calculation.

## Docker

Review the existing frontend Docker setup and make sure the frontend can be built and served as a production container.

Requirements:
- use a multi-stage Dockerfile
- use an official Node image for the build stage
- install dependencies and build the Vite application inside the build stage
- serve the generated production files from a lightweight web server such as Nginx
- do not require Node or npm in the final runtime image
- expose the frontend through port 80 inside the container

The image should be buildable with:

docker build -t calculator-frontend .

The container should be runnable with:

docker run --rm -p 3000:80 calculator-frontend

The frontend should then be available at:

http://localhost:3000

Make sure the frontend can be configured to call the backend without hardcoding environment-specific URLs directly inside UI components.
